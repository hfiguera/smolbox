# SmolBox 0.4.0

SmolBox 0.4.0 helps you operate persistent workspaces: inspect resource usage,
pause new admissions for maintenance, grow a machine's disks and keep project
data when replacing the machine. The default worker remains **smolvm 1.20.2**.

## Upgrade first

**Coordinate every controller and store reader before deploying.** The PostgreSQL
example adds migrations for worker admission controls and local volumes. Disk
expansion and volumes selectively use codec v14/v15; old readers cannot decode
their history, including records retained after deletion. Old writers can bypass
drain gates and omit volume accounting.

Draining now requires `worker_control: 1`. Unsupported adapters return
`:unsupported_capability` instead of changing only one controller's state.
Ordinary disposable execution and retained-machine APIs remain available.

Read [Upgrading to 0.4.0](https://hexdocs.pm/smolbox/0.4.0/upgrading-to-0.4.0.html)
for the deployment sequence, optional adapter contracts and rollback constraints.
Updating the package does not install smolvm or change checkpoint runtime pins.

## Changes

- **Explain resource usage.** Typed machine measurements and worker reports show
  CPU, memory, disk and outbound network observations alongside durable reservations.
  Admission explanations identify shortages without changing resource limits.
  Optional counters remain unavailable when the worker cannot supply them.
- **Coordinate maintenance.** Durable draining blocks new admissions across
  controllers sharing a store, survives restart and uses versioned resume. Bounded
  maintenance reports expose remaining assignments and retained resources.
  Draining does not stop machines or cancel requests already sent.
- **Grow retained disks.** Expand storage and overlay disks on idle stopped or
  created machines with smolvm 1.20.2. Preserve creation identity, reserve growth
  atomically and retain uncertainty for explicit recovery. Disk growth does not
  start the machine or guarantee immediate guest filesystem readiness.
- **Keep data across machine replacement.** Managed local volumes on Linux 1.20.2
  have independent identity, reservations and explicit deletion. Controlled mounts
  allow one exclusive attachment per volume. Delete the original machine, then
  attach the same volume to its replacement on the same worker.

## Evidence and limits

The [compatibility guide](https://hexdocs.pm/smolbox/0.4.0/compatibility.html)
links the separate physical Linux campaigns: machine measurements, PostgreSQL
drain recovery, disk growth with file preservation across controller restart,
and volume reuse with replacement writes, read-only mounts and verified cleanup.
Simulated worker and memory/PostgreSQL contract tests separately cover concurrency,
store failures, uncertain outcomes and rollback guards.

Those campaigns are feature evidence, not a combined maintenance campaign or a
claim that the final release artifact was tested live. No new macOS campaign is
claimed. Volumes are Linux only; root-worker per-VM UID isolation is not qualified.
Volume sizes are advisory reservations, not enforced quotas. Mounted machines
cannot currently be exported, checkpointed, branched or expanded. Disk expansion
also excludes checkpoint and branch machines. Qualification remains `:development`.

These are draft release notes. Final commit CI, bounded live release checks, tag
creation, Hex publication and documentation availability must be confirmed
separately from preparation.
