## Correction and scope

The initial RC2 candidate, `54ade3c`, failed its GitHub minimum-toolchain lane:
a maintainer test inspected a child process after a fixed 50 ms delay and could
observe the launch shell before it executed the intended binary. Candidate
`9ce713f` replaces that assumption with a bounded check for the post-exec process
title and deliberately delays launch in the regression. All required checks were
rerun at the replacement candidate. The initial failed CI run is retained in the
evidence and is not counted as a pass.

The accepted scope remains the tested client/controller contract with
`:development` workers. Production resource/isolation certification, protected
real-worker GitHub infrastructure and independent consumer review remain excluded
under section 1.4. No production profile is certified. Unsupported hard controls
stay rejected; uncertain commands are never silently replayed, and upstream
receipt/fencing, cancellation and canonical-path limitations remain documented.

To reproduce, use a clean checkout of the candidate, the pinned toolchains and
native artifacts, and the commands in the JSON. The
[CI guide](../../scripts/ci/README.md) describes preflight, bounded suites, private
databases and service-fault setup. Raw final-candidate evidence is retained under
`/tmp/smolbox-rc2-final.Pci7oW` on both hosts; task-owned database state is under
`/tmp/smolbox-rc2-validation.e1FJw4`. The validated archive is also retained locally
in ignored `_build/releases/0.1.0-rc.2/`.
