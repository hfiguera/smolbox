# SmolBox 0.6.0

SmolBox 0.6.0 adds per-child configuration and networking to held branches.
SmolVM **1.34.0** remains the default for both backends.

## Changes

- Give each held child its own non-secret environment values at release on
  HTTP workers and Embedded Port. Release retries bind the original version
  and exact environment to the accepted operation.
- Enable opt-in allowlisted branch egress on Linux x86_64 for both backends.
  Approved CIDR and hostname checks cover both siblings after release and
  again after stop/start. Portable checkpoints remain offline.
- Authorize HTTPS Bearer credentials independently for each held child and
  approved destination on both backends on Linux x86_64. Keys stay on the host.
  Embedded Port resolves a fresh binding before release and each restart;
  unbound children cannot inherit a parent or sibling key.
- Fix macOS held-child restore with an existing normal source cache and align
  Rust/Elixir release-environment hashing, including vertical-tab escaping.
- Document production support by backend, host, feature and store. Existing
  `qualification: :development` configuration remains compatible and is deprecated.
- Reduce duplicate CI work, cancel superseded PR runs, cache native compiler
  outputs, and add focused local pre-commit/pre-push checks.

## Upgrade

```elixir
{:smolbox, "~> 0.6.0"}
```

Upgrade every reader, writer and custom adapter sharing the store before
accepting the new records. Release environments require codec v51 and
`branch_release_env: 1`; static egress requires v52 and `branch_static_egress: 1`;
Embedded Port HTTPS credentials require v53 and
`native_branch_https_credentials: 1`. The supplied Memory store supports these
capabilities. Durable adapters must implement the atomic transitions before
advertising support. No SQL migration is added for these features.

Install and approve the matching Embedded Port bundle. Preserve prior helper
paths, owned domains, checkpoint version pins and unknown work through the
normal drain/recovery procedure. Existing native packages retain their original
feature approvals. Non-secret release values are persisted; direct plaintext
secret injection is outside the supported credential contract. Running children
retain an installed HTTPS key until stopped.

## Branch feature validation

The implementation campaigns recorded the following live results before release
artifact preparation:

- Both held siblings received their own release environment values through
  HTTP and Embedded Port, including the macOS restore with its normal cache.
- Both backends passed approved/denied CIDR and hostname egress probes on Linux
  x86_64 for each sibling after release and after stop/start.
- The Embedded Port HTTPS campaign verified distinct dummy keys at
  `https://httpbingo.org/headers` for both siblings after release and stop/start.
  `example.com` remained blocked; an unbound child stayed held, and revoking a
  stopped child's binding denied restart before native dispatch. Reauthorization
  restored startup. Control VMs reached both destinations before and after.
- Both Embedded Port campaigns finished with empty VM inventories and no
  retained reservations. The protocol, authority and cross-language regression
  tests passed.
