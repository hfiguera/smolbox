## Scope and remaining boundaries

The runtime evidence concerns Linux x86_64, synchronous block I/O, approved
Python/Node artifacts, and the documented disposable nested KVM configuration.
New packing tests used `pack create --from-vm` with the original approved layers;
they do not qualify a fresh registry pull, every OCI image or every `USER`
inheritance path. Explicit UID 65534 execution was tested through buffered and
streaming HTTP operations.

The constrained worker controls and workload probes do not establish universal
hostile-code isolation, concurrent tenant safety, asynchronous block I/O,
Linux ARM64 or macOS 1.14.6 compatibility. SmolBox's supported qualification
remains `:development`, and unsupported hard controls remain rejected. Host
tasks are not guest PIDs, charged memory is not per-process RSS, and CPU
bandwidth is not accumulated CPU time. External recovery remains necessary
when an API failure leaves machine state unresolved.

The captured SSE fixture intentionally preserves the upstream empty `data: `
field and frame-ending blank line. Git's whitespace checker flags those bytes;
they are retained as wire evidence. Other changed files passed whitespace checks.

One final rebuilt-artifact attempt stopped at the checksum read before worker
startup: restoring the packer's mode-0600 outputs as root made them unreadable
to the controller. The catalog was corrected to root-owned mode 0444 and both
payload digests matched. This changed the disposable fixture's file permissions,
not artifact bytes, the candidate source or the worker's resource controls.
