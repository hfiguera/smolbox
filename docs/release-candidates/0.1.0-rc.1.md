[implementation plan §1.4](../implementation-plan.md#14-first-release-scope-decision-september-7).

The live wrappers required exactly 14 and 25 executed tests respectively and
rejected skipped, excluded or partial results. Existing cases cover authenticated
TLS forwarding, Python/JavaScript, binary files/output, timeouts, finite output
and file boundaries, controller SIGKILL/restart, dispatch uncertainty, artifact
outage, notification faults and cancellation around SQL result commits. Passing
a test that characterizes an upstream limitation does not establish isolation.

Normal demos returned exit zero, completed collection/cleanup and released
reservations. Cancellation demos preserved an unknown exit result while recording
confirmed termination, completed cleanup and released reservations. The service
fault scenarios passed their assertions and owned-resource teardown.

The runtime was SmolVM **1.14.1**, source commit
`e8d09ef616d363004d55b80a6cdb31a4e7e1842d`. Preflight on the actual hosts checked
native architecture, executable/wrapper pins, prepared Python/Node artifact
hashes, listener ownership, health/readiness and empty inventory; Linux also
verified KVM access. The JSON report retains each platform's distinct binary and
artifact digests. Hosts were Darwin 25.6.0 arm64 and Linux
7.1.5-76070105-generic x86_64, using Elixir 1.20.4/OTP 28.5 for real tests.

Each host used its own task-owned PostgreSQL **16.15** instance on Linux, with
20 connections, no TCP listener and a private Unix socket. macOS accessed only
its instance through a task-owned SSH socket forward. These independent databases
allowed simultaneous host suites without sharing the connection budget. Stopping
each actual instance produced the expected store errors; it was restarted before
subsequent recovery tests. The pre-existing shared database was left running.

Final preflights again verified both original workers were healthy with empty
inventories. Fault-worker API/guest ports were free. Both private databases had
zero reserved slots and zero due-work records before being stopped, and the
owned SSH forward was closed. Private durable records/keys were retained; no
unrelated worker, database or upstream checkout was reset or deleted.

## Corrections and retained limits

No candidate source correction was required by this matrix. Two local setup issues
were corrected and retained in the evidence: PostgreSQL's extracted tools lacked
`createdb`, so setup used `psql`; and compiling the minimal example's SmolBox path
dependency before the dependency graph cached undefined-module warnings. Rebuilding
the full graph in order removed those warnings on both hosts. Compilation and
Dialyzer were rerun successfully; the initial functional demos and logs remain
recorded rather than being described as warning-free runs.

The accepted scope remains the tested client/controller contract with
`:development` workers. Production resource/isolation certification, protected
real-worker GitHub provisioning and independent consumer review are excluded
under the maintainer's decision; none is claimed completed or scheduled.
Unsupported hard controls stay rejected. SmolVM has no verified durable exec
receipt/fence, uncertain outcomes are never silently replayed, cancellation has
no stronger termination guarantee, and lexical paths do not establish canonical
workspace containment. See the packaged security and recovery guides.

For reproduction, use a clean checkout of the candidate and the commands recorded
in the JSON, with the pinned toolchains and native artifacts. The
[CI infrastructure guide](../../scripts/ci/README.md) documents preflight, bounded
live suites, private database requirements and service-fault setup. Local raw
reports are retained under `/tmp/smolbox-rc-validation.blcSHc` on both hosts; the
validated archive is also retained in the local ignored
`_build/releases/0.1.0-rc.1/` directory.
