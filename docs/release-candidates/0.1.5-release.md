## Upgrade requirements

**Upgrade every controller sharing a store before submitting checkpoint work.**
Checkpoint executions write schema-v3 records, including completed records that
older controllers cannot read. Disabling new checkpoint submissions alone does
not make rollback safe. Image records retain v2 and their existing fingerprints.
No SQL migration is introduced. See the [upgrade procedure](../recovery.md#upgrading-to-0-1-5).

smolvm 1.16.1 remains the default and is required for checkpoints. Existing image
execution support remains unchanged. Applications coming from 0.1.2 or earlier
must also account for v2 adoption; those coming from 0.1.3 must account for the
worker default change in 0.1.4.

- Six consumers of the same prepared archive: current and minimum dependencies

  27.3.4.15, on each host.

  repository metadata and 179 tagged source file/line links were checked.

Both dedicated runtime inventories were empty at completion, and the workers
and private databases were stopped. Setup corrections are retained in the JSON

test selection rejected by the strict reporter. Corrected invocations passed;

checksum and all installed files, compiled and passed public API/supervisor smoke
checks. These consumer checks use a synthetic transport, not live workers.

Five public documentation pages report version 0.1.5. The upgrade anchor, tagged
checkpoint source, and all three hosted checkpoint evidence assets were verified.
The GitHub release asset digest matches the downloaded Hex archive.

## Evidence boundaries

Fresh native runtime checks cover ordinary checkpoint execution. The private
database tests exercise the store contract; they are not a new full durable
checkpoint recovery campaign. Earlier focused Linux recovery and performance
measurements retain their recorded revisions and scope. No new image runtime,
network enforcement, exhaustion, adversarial or performance campaign is claimed.

Only approved idle, offline checkpoints are supported. Capture, live branching,
pools, networked checkpoints and arbitrary resumed workloads remain excluded.
The full checkpoint failure matrix, macOS durable checkpoint recovery, macOS IPv6
and Linux ARM64 remain outside the evidence. There is no new production isolation
or hard host quota guarantee.

This report is excluded from the Hex package. Its later commit does not move the
release tag or change the published archive.
