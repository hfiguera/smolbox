# SmolBox 0.1.0 release validation and publication

Status: **published and verified**, September 7, 2026, within the development-qualified
first-release scope in [implementation plan §1.4](../implementation-plan.md#14-first-release-scope-decision-september-7).
The maintainer explicitly authorized the tag, Hex/HexDocs publication and GitHub
Release after successful validation. This is separate from the earlier RC-only
work, which published no package.

after every validation step; cached dependency graphs were force-compiled.

## Package and publication checks

One archive was built and used by all four fresh production consumers: current
dependencies on the canonical pair and minimum direct dependencies on Elixir
1.18.4/OTP 27.3.4.15, on both hosts. They passed warning-as-error compilation and
public client/supervisor smoke checks with only the nine runtime dependencies.
Every packaged file matched the candidate Git object. Examples, analyzers, tests,
scripts, external references and release attestations were absent from the package.

Version, changelog, GitHub metadata, normalized SPDX MIT text and runtime dependency
license declarations/notices were reviewed. Hex reported the name absent before
publication; the published package ownership was verified afterward.

The successful `mix hex.publish --dry-run --yes` built the package and documentation
without uploading. Rebuilding the archive produced identical bytes. An earlier
invocation without `--yes` waited at its interactive prompt and was terminated;
its zero process exit was **not** accepted as dry-run success. The completed rerun
and the initial interrupted log are retained separately.

After all required checks passed, the tag was pushed and verified, then
`mix hex.publish --yes` ran from the clean release source with an authenticator
OTP. An initial noninteractive attempt was stopped at the OTP prompt; registry
absence was verified before retrying interactively. The OTP is excluded from
recorded evidence. The downloaded public Hex tarball was byte-for-byte identical
to the validated archive and matched the
Hex release checksum. Two additional fresh consumers fetched the documented
`{:smolbox, "~> 0.1.0"}` dependency from Hex on macOS and Linux, compiled it,
exercised the public client/supervisor and matched all 84 source-file hashes.

HexDocs' index, README, getting-started guide and main API page responded
successfully with the expected version/content and source links. The GitHub
Release was published only after package and documentation verification. Its
existing tag, published state and release notes were checked afterward.

## Scope and retained evidence

This is the tested development-qualified client/controller release. Production
resource/isolation certification, protected real-worker GitHub provisioning and
independent consumer review remain outside section 1.4's scope. No production
profile is certified. Unsupported controls stay rejected; upstream fencing,
uncertain-outcome, cancellation and path-containment limits remain documented.

This report, its JSON companion and the implementation plan are repository-only
attestation files. Their later commit does not replace the tested release commit
or move any tag. RC1 and RC2 tags/evidence remain intact.

Raw local evidence and task-owned database state are retained at
`/tmp/smolbox-release-010.M6AMHg` on both hosts. The validated archive is also saved in the local ignored
`_build/releases/0.1.0/` directory. Use the commands and identities in the JSON and
[CI guide](../../scripts/ci/README.md) to reproduce the validation.
