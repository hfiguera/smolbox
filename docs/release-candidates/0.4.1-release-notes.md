# SmolBox 0.4.1

SmolBox 0.4.1 qualifies smolvm **1.22.0** and makes it the default on Linux
x86_64 and macOS Apple Silicon. It retains the APIs introduced in 0.4.0 and fixes
a timing assumption in the provisioning benchmark.

## Upgrade note

**If your worker still runs 1.20.2, explicitly set `runtime_version: "1.20.2"`
before upgrading SmolBox, or upgrade the worker separately.** Keep checkpoint
approvals pinned to their capture runtime. Updating the package does not install
smolvm or convert existing checkpoints.

There is no SQL migration, new store capability or codec revision from 0.4.0.
Older readers can reject records containing the new runtime version. Upgrade
shared controllers and readers before producing those records; reverting
application code alone is not a complete rollback.

Read [Upgrading to 0.4.1](https://hexdocs.pm/smolbox/0.4.1/upgrading-to-0.4.1.html)
for the deployment sequence and earlier-release migration requirements.

## Changes

- Admit the official 1.22.0 runtime and update binary pins, worker protocol
  fixtures, example defaults and documentation. Earlier supported runtimes remain
  available through explicit configuration.
- Let the provisioning benchmark accept either `created` or `stopped` before
  explicitly starting a fresh machine. The upstream supervisor can mark an
  unstarted machine stopped on both 1.20.2 and 1.22.0; two contract tests cover
  this behavior.
- Record Linux and macOS qualification, follow-up investigation and the extra
  host capacity needed for upstream image seed preparation and caching.

## Evidence and limits

The [runtime qualification report](https://hexdocs.pm/smolbox/0.4.1/runtime-1.22.0-qualification.html)
records the preceding physical Linux and native macOS campaigns, their exact
inputs and cleanup evidence. Coverage includes execution, durable recovery,
terminals, files, networking, checkpoints, branches and disk growth. Linux also
covered retained volumes, durable draining and the five-mode provisioning
comparison. Feature coverage differs by platform; see the report for details.

One initial macOS Node creation returned HTTP 500. Its response body was not
retained and the failure did not recur in matched diagnostic campaigns on 1.20.2
and 1.22.0. Its cause remains unknown. It is retained as a non-blocking observation,
not presented as a fixed defect or a confirmed regression.

Qualification remains `:development`. Cross-version checkpoint restore,
in-place upgrades of retained worker state and upstream database rollback are
not established. Terminal cleanup observations do not establish guaranteed
cancellation or justify replaying an unknown command.

These are draft release notes. Final exact-commit CI and bounded real-worker
checks, tag creation, Hex publication and documentation availability must be
confirmed separately from preparation. The preceding qualification is evidence
for the runtime change, not a claim that the final release commit was tested live.
