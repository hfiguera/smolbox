## What native testing found

The official SmolVM 1.14.6 Darwin release ran natively on macOS 26.6.2, build
25G83, using Apple Silicon virtualization. Binary, agent, library and OpenAPI
identities were checked before execution. The running VMM mapped the expected
1.14.6 libraries. Existing host services and the approved ARM64 payloads were
preserved.

**A working host `resize2fs` is required for disk requests smaller than the
bundled templates.** The initial 1/1 GiB test lost a written file after stop/start.
Direct HTTP calls reproduced the loss without SmolBox's client. Matching
20/10 GiB requests retained the file, as did both requests on the existing
1.14.1 worker. Source and logs showed unsuccessful disk shrinking when the tool
was missing, followed by template replacement on a subsequent launch.

Supplying private e2fsprogs 1.47.4 made the original persistence test pass without
changing its assertions. Fresh Python and Node artifacts also passed the nine
ordinary runtime cases. Each requested disk measured 1,073,741,824 bytes and
had its formatted marker. These observations establish the tested prerequisite
and behavior, not hard host storage quotas. The conservative managed profile's
20/10 GiB floors remain unchanged.

Testing the exact TCP getting-started example also found that it passed
`unix_socket: nil` when the environment variable was absent. That configuration
was rejected before dispatch. The walkthrough now adds the option only when a
socket is supplied; its TCP and Unix-socket forms both passed.

The [preparation evidence](../evidence/smolvm-1.14.6-macos.json) preserves the
initial failures and successful comparisons. The final JSON separately records
fresh artifact identities and results. Those artifacts were packed from approved
local layers; this does not qualify arbitrary registry images. Packing needed
a separate bounded file-transfer allowance, while the API worker retained its
smaller file limit.

## Cleanup and boundaries

Final stores contained zero pending records or reserved slots. All task workers,
their VMs and the private Mac database were stopped. The original Mac worker
and database remained running. The temporary sleep inhibitor was removed.

On Linux, the outer VM and its cgroup were absent, its private management port
was closed, and the recovery controller recreated a clean disposable disk from
the unchanged baseline. The recovery timer and original physical-host worker
and database were preserved.

Exhaustion and adversarial execution remained in the disposable Linux lab.
The five boundary cases excluded on macOS ran in the Linux runtime suite. The
earlier constrained Linux exhaustion campaign and full 1.14.1 acceptance remain
separate evidence; neither is claimed as a fresh run in this follow-up. No hard
macOS host limits, universal hostile-code isolation or new production deployment
qualification is established here. SmolBox's qualification remains `:development`.

The package is prepared for a separately authorized release. Public `v0.1.2`
documentation/source links become available when that release is published.
