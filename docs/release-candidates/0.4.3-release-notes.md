# SmolBox 0.4.3

SmolBox 0.4.3 improves runtime reliability and makes the first execution easier
to follow. The default worker remains **smolvm 1.22.0**.

## Changes

- Cancellation, queue expiry, machine lifecycle work and cleanup continue through
  one bounded maintenance task when execution slots are occupied.
- Branch and checkpoint preflight require the configured worker version and
  readiness. Active execution and machine I/O deadlines account for monotonic
  elapsed time, preventing extension when the wall clock moves backward.
- Image completion telemetry handles image results correctly. The community
  workspace example restores a missing runtime during refresh before reporting
  readiness; its dependency remains pinned to the published 0.3.0 walkthrough.
- Guides use clearer navigation and setup order, separate testing reports, and
  focus upgrade instructions on user actions. The complete Getting Started
  Livebook is included in the package and HexDocs.
- Protected Linux and macOS qualification now checks the actual Livebook's
  execution, exact stdout and collected file, reservation release and VM cleanup.
  Maintainer preflight accepts the official pinned worker launchers.

## Upgrade

```elixir
{:smolbox, "~> 0.4.3"}
```

From 0.4.2, no SQL migration, codec revision, error category or store capability
is added. Restart controllers through the normal coordinated deployment process
and preserve worker pins and durable identities. Execution task limits remain;
task-count monitoring should account for one maintenance task and one scan task
alongside those execution tasks.

Read [Upgrading to 0.4.3](https://hexdocs.pm/smolbox/0.4.3/upgrading-to-0.4.3.html).
Applications on earlier releases must also follow the intervening upgrade guides.

## Release status

These are preparation notes. Version 0.4.3 has not been published or tagged.
The versioned links above become available after publication. Candidate checks
do not establish that a future published package or final release commit has
passed verification. Supported use remains `:development`; deployment resource
limits and worker access remain operator responsibilities.

## Local release verification

The [candidate verification record](0.4.3-verification.json) records the package
digest, host details, outcomes and remaining publication checks.

The candidate was prepared on `release/0.4.3` from main `a8a85fe`.
The results below describe the uncommitted package contents, rather than a final
release commit or published Hex dependency.

- Deterministic CI passed 636 checks on both Linux and macOS (4 doctests, 6 properties and 626
  tests), excluding 29 worker tests. Formatting, compilation, xref, Credo, ExDNA,
  Credence and Dialyzer passed. The standalone CI tooling suite passed 31 tests.
- ExDoc built without warnings and the documentation checker validated local
  links and fragments across 137 pages, including the downloadable notebook and
  the new upgrade guide.
- Clean production consumers passed the same archive on Linux x86_64 and macOS
  ARM64 with Elixir 1.20.4 / OTP 29.0.6. The minimum consumer passed on macOS with
  Elixir 1.18.4 / OTP 27.3.4.15 and exact minimum direct dependency versions.
  The production dependency lock was unchanged.
- The actual Getting Started Livebook passed all six evaluated cells and seven
  assertions on Linux and macOS with smolvm 1.22.0 and Livebook 0.19.10. They checked
  completion, exact stdout, the collected `42` file, VM deletion, released
  reservations, empty inventory and supervisor shutdown.
- Nine real worker tests passed on each host, covering Python and JavaScript,
  binary files, nonzero exits, timeouts, offline networking, an authenticated TLS
  proxy, managed cancellation, delayed dispatch and cleanup. The runtime source
  used by those tests matched the shipped archive bytes.
- `mix hex.audit` and `mix deps.audit` reported no advisories or vulnerabilities.

Both platforms used the identical archive, SHA256
`2de553a8f481626b55c9b51e96992a2bdd20e638432c59edfc0de2cd9c0a0251`.
The verifier replaced only the notebook dependency with its unpacked candidate
package and filled the documented worker URL, image path and SHA256 configuration.
The execution and cleanup cells were unchanged; a separate verification cell
checked the results.

These normal workload checks do not repeat the full resource abuse, saved-state,
PostgreSQL recovery or worker compatibility campaigns. Earlier qualification
reports retain their original revisions and scope. Published-package checks and
final release commit CI remain necessary before announcing 0.4.3.

The owned workers and verifier processes were stopped, and the proof's temporary
workspaces and image downloads were removed. The dedicated macOS account, home
and test marker were removed after saving the reports. Preexisting Apple services
and cache directories were left untouched. A temporary reporting parser initially
rejected the newer ExUnit success summary despite passing tests; corrected retries
passed on both hosts without a production code change.
