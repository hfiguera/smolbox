# Terminal disconnect article

Mode: Read. Extend the established technical field guide; preserve its typography,
palette, article template and navigation. The user approved the topic and a
browser → controller → guest interaction, building directly in the browser.

Reader question: after a terminal disconnect, what evidence makes the next
command safe? Success is distinguishing a surviving application session owner,
a lost guest connection and an observed exit, then finding the runnable example.

The figure offers three reader-selected scenarios with manual steps and finite
playback. Broken connections change both line treatment and text; uncertain guest
state is never animated as proven continuing execution. Reduced motion suppresses
packet animation. Leaving view or hiding the tab pauses playback. No worker
requests, replay, analytics events or remote dependencies are added.

The article uses 0.2.1 APIs and links to versioned guides/source. The community
workspace's local reconnect policy is separate from the library and its package
lock remains 0.2.0. New evidence covers three native macOS terminal tests, the
durable observed-exit demo, and five simulated browser owner tests. It makes no
new browser/network or Linux qualification claim.

Quality bar: visible loss boundary, readable labels on phones, useful static
fallback, no automatic playback, and actions that explain rather than obscure
uncertainty. The social graphic is original geometric SVG, rasterized locally.
